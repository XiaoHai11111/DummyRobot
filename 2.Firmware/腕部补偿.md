# F4 腕部重力与低速助力补偿

本文记录 F4 侧默认重力模型、J4/J5 候选参数、F1 v2 协议和通电前后复验流程。实机已复验 USB/CAN v2 握手和两腕精确速度测量；本次 J4/J5 每轴限流 3 A、夹爪闭合空载、相机已安装且数据线接着。拖动（DRAG）助力验收尚未进行，旧表仍为默认候选。

## 1. 默认行为

- 上电和 `#WRIST_RESET` 后，六轴位置模式重力前馈恢复 HEAD 电流模型，原总开关 `#GRAVITY_FF_ON` / `#GRAVITY_FF_OFF` 继续控制位置模式。
- 新 MJCF 腕重力独立默认关闭，`#WRIST_GRAVITY 4 0` 和 `#WRIST_GRAVITY 5 0` 对应 scale 0。
- 拖动模式继续保留 HEAD 的 J5 旧重力曲线。该曲线只在未使用新腕重力混合时作为 J5 基线。
- 新模型使用当前 MJCF 的零速静态 holding torque，包含 `wrist3_link`、左右夹爪和 `0.14425 m` 的腕部安装距离。
- 新腕重力只影响 J4/J5。J2/J3 的 HEAD 电流参数和 65 姿态基线保持不变。

新重力在 F4 中的混合公式为

```text
i_axis = i_head + scale * (clamp(k * tau_mjcf + bias, limit) - i_head)
```

`tau_mjcf` 是关节正向的零速静态重力矩，`i_head` 是原位置模式或拖动模式中的轴电流。scale 范围是 0 到 1。

代表姿态 `[0, 0, 90, 0, 0, 0] deg` 的 MJCF 腕力矩为

| 轴 | 静态力矩 N·m |
| --- | ---: |
| J4 | -0.0013025755 |
| J5 | -0.1341844936 |

## 2. 离线候选参数

| 轴 | k A/N·m | bias A | 电流上限 A | 数据背景 |
| --- | ---: | ---: | ---: | --- |
| J4 | 0.9342749 | 0.0100611 | 0.500 | 当前夹爪相机安装与 J4/J5 减速器研究导出 |
| J5 | 0.9494676 | 0.0031513 | 0.500 | 旧拔线组初始候选，现场必须用当前新批次重标 |

这些参数是 RAM 中的离线起点，不是已验证的现场负载参数。J5 旧拔线组与当前夹爪、相机、线束的连接状态不同，默认必须保持 scale 0。现场复验必须使用夹爪闭合、空载、相机装机且线束按实际新批次连接的配置，并重新确认或更新候选参数后才能逐轴放大。当前仍以本表为默认候选，此时尚无拖动验收。

原始 F1 电机域谐波参数为

| 轴 | E sin mA | E cos mA | O sin mA | O cos mA |
| --- | ---: | ---: | ---: | ---: |
| J4 | 46 | -84 | -70 | -33 |
| J5 | -25 | 57 | 41 | 22 |

这些系数由电机域相位得到，F4 原样发送，不做关节与电机符号缩放。

## 3. F1 v2 帧

### 0x0D 与 0x28

`0x0D` 写四个有符号小端 `int16` 电机相位系数，单位 mA。

```text
[E_sin_mA, E_cos_mA, O_sin_mA, O_cos_mA]
```

`0x28` 使用同一 8 字节格式回读。F4 的 `#WRIST_HARMONIC` 只改 RAM 参数，不写 EEPROM。

### 0x0E

```text
[0xB4, 2, enable_u8, gain_percent_u8, sequence_u16_le, assist_cap_mA_u16_le]
```

| 字段 | 范围与含义 |
| --- | --- |
| enable | 1 启用本地新模式，0 关闭 |
| gain | 0 到 100 百分比，作用于库仑、粘滞和谐波的全部附加项 |
| cap | 0 到 500 mA，只限制新算法附加项 |
| sequence | 非零单调应用序号 |

停用必须同时发送 gain 0 和 cap 0。速度测量单独启用时使用 enable 1、gain 0、cap 0。

`0x27` 回读继续使用原 8 字节格式，版本必须为 2。

```text
[0xB4, 2, flags_u8, direction_i8, actual_assist_mA_i16_le, sequence_u16_le]
```

`flags` bit0 表示本地新模式启用，bit1 表示精确速度窗口已就绪。bit1 不是配置使能位，速度窗就绪不等于本地助力已启用。F4 只有在最新写入的 sequence、enable 和预期状态一致后才把该轴标记为已验证。旧版本、短帧、异常 direction 或异常电流不会刷新验证计数。

### 0x0F

```text
[base_motor_mA_i16_le, total_limit_mA_u16_le,
 sequence_u16_le, lease_flags_u16_le]
```

- `base_motor_mA` 已经完成关节到电机方向转换。
- `total_limit_mA` 范围是 1 到 3300，并且不能超过 F1 额定电流。
- `lease_flags` 低 14 位是原 lease 毫秒数，范围沿用它原来的检查。
- bit14 为 1 时禁止正电机电流。
- bit15 为 1 时禁止负电机电流。
- 总限流和方向限制同时作用于 base、库仑、粘滞和谐波附加电流。
- `0x0F` 只发到节点 4 和 5，绝不使用节点 0 广播。

F4 只在 v2 握手、0x28 谐波回读和 0x27 sequence 状态全部通过后发送 `0x0F`。处于新算法 opt-in 状态时，旧 `0x0B` 帧不会获得新助力。未配置腕速率的轴仍使用原 `0x0B`。

未选择新协议的 J4/J5 不会主动查询 0x27/0x28，也不会因旧 F1 没有 v2 应答而失去 HEAD 拖动。旧节点只有在请求 `#WRIST_SPEED`、`#WRIST_FRICTION` 或 `#WRIST_RESET` 新功能时才进入 v2 握手，握手失败后保持 HOLD。一个腕轴已进入扩展模式、另一个仍为默认模式时，两者分别使用 `0x0F` 和 `0x0B`。

F4 根据关节机械限位和超速阈值生成危险方向位，再做电机方向转换。即使 base 电流恰为零，端停附近仍会置位，以阻止 F1 本地附加电流继续朝危险方向输出。

## 4. F4 RAM 配置命令

配置命令只在 F4 停止时接受。`#GETWRIST` 只读，可用于确认当前状态。

```text
#GETWRIST 4
#GETWRIST 5

#WRIST_GRAVITY_MODEL 4 0.934275 0.010061 0.500
#WRIST_GRAVITY_MODEL 5 0.949468 0.003151 0.500

#WRIST_HARMONIC 4 46 -84 -70 -33
#WRIST_HARMONIC 5 -25 57 41 22

#WRIST_GRAVITY 4 0.000
#WRIST_GRAVITY 5 0.000

#WRIST_SPEED 4 1
#WRIST_SPEED 5 1

#WRIST_FRICTION 4 0.250 200
#WRIST_FRICTION 5 0.250 200

#WRIST_RESET 4
#WRIST_RESET 5
#WRIST_RESET
```

`#WRIST_SPEED j 1` 只启用精确速度测量，不产生本地助力。`#WRIST_FRICTION j scale cap` 同时启用速度和本地新模式。`#WRIST_RESET` 先确认零助力关闭，再清除该轴 RAM opt-in 和重力配置并恢复默认模型。

原来的 `#LOCALCOMP`、0x0C 和 EEPROM 保存路径保持兼容。`#WRIST_FRICTION` 不发送 0x0C，也不修改旧 local limit。

## 5. 停机与故障规则

- 任何正常 STOP、拖动退出或故障都会清除力矩租约，并对 J4/J5 发送零 gain、零 cap 帧。
- 实机已确认 `!STOP` 后 F1 进入主动位置 HOLD（保持当前位置），F4 腕轴零助力帧同时生效；DRAG 模式 5 的拖动/助力验收仍须单独执行，不能由 STOP 行为替代。
- 已显式配置速度测量的轴可以继续保留 enable 1、gain 0、cap 0。此时只提供新速度窗和诊断，不提供助力。
- STOP/HOLD 后再次 START 时，扩展轴先在任意控制 tick 重新查询 0x27，并确认速度和 sequence。重新确认前不会向该轴发送旧 `0x0B`，也不会发送未确认的 `0x0F`。
- 若 STOP 的零助力写入或后续状态应答丢失，sequence 校验失败会让该轴保持 HOLD 并使拖动安全停止。恢复时必须重新完成状态握手。
- 紧急 STOP 使用全局 HOLD 和腕轴零助力帧，不阻塞等待查询。
- CAN 写失败、回读失败、版本错误或 sequence 不匹配时，轴不进入已验证状态。F4 发 HOLD，后续拖动不会再对该轴发旧 `0x0B` 助力。
- 已发送但未确认的 `0x0E` 会由新的零助力 sequence 覆盖。仍无法确认时保持 HOLD。
- 周期查询失败会清除 speedEnabled、frictionEnabled 和 controlVerified，不会沿用上一次“已开启”状态。
- 周期状态超过速度有效窗后会重建 speed-only 状态并关闭助力。重建失败则 HOLD 并撤销协议验证。
- 所有新参数只在 RAM 中生效，掉电恢复默认关闭状态。

## 6. 现场复验流程

先确认机器人周围无人、急停可用、夹爪闭合、相机和线束处于本次要验证的实际状态。

1. 发送 `!STOP`，确认机器人停止并保持。
2. 发送 `#GETWRIST 4` 和 `#GETWRIST 5`，记录默认参数、谐波回读和 v2 状态。
3. 先用 `#WRIST_SPEED 4 1`、`#WRIST_SPEED 5 1` 验证速度测量和 STOP 行为，不启用助力。
4. 将某轴重力 scale 从 0.10 或 0.25 开始，逐次增加。每次 `#GETWRIST` 确认 version 2、sequence 和 flags。
5. 需要低速助力时使用小 cap，例如 `#WRIST_FRICTION 4 0.10 100`。观察方向、温升、噪声和漂移后再增加 gain。
6. 发送 `!START`，进入 `#CMDMODE 5`，低速手动扫描 J4/J5。
7. 用 `#GETTELEM 4` 和 `#GETTELEM 5` 记录位置、速度、状态和电流。位置采集流程仍为 `!STOP -> !START -> 扫描 -> !STOP`。
8. 最后发送 `!STOP`，再次读取 `#GETWRIST`。若先前显式启用了速度测量，应仍看到 `s1`，但助力应显示为 `f0.000` 或零 cap 状态，actual assist 电流应为 0。
9. 需要再次 `!START` 时，确认扩展轴先完成 0x27 状态重同步。若启动后安全停止，检查最后的 `#GETWRIST`、CAN 写错误和状态超时，再重新配置。
10. 试验结束发送 `#WRIST_RESET`，使 J4/J5 回到默认关闭配置。

示例观察命令

```text
!STOP
#WRIST_SPEED 4 1
#WRIST_SPEED 5 1
#GETWRIST 4
#GETWRIST 5
!START
#CMDMODE 5
#GETTELEM 4
#GETTELEM 5
!STOP
#GETWRIST 4
#GETWRIST 5
#WRIST_RESET
```

## 7. 验收结果

F4 宿主测试覆盖了以下内容

- HEAD 代表姿态和 65 姿态旧电流基线。
- 当前 MJCF 的 J4/J5 静态腕力矩。
- 0x0D 原始谐波、0x0E gain/cap/sequence、0x27 版本和 sequence。
- 0x0F 节点限定、总限流、J4 双向限位位、J5 电机反向映射、base 为零时的危险方向位。
- 默认旧 F1 路径、新旧 F1 混合路径、旧节点请求新功能的拒绝路径。
- CAN 发送失败、参数回读失败、版本错误、sequence 错误和状态轮询失败。
- STOP/HOLD 到 START 的状态重同步、STOP 应答丢失时拒绝旧 0x0B、STOP 后 speed-only 状态和零助力关闭。

实机测速记录：[wrist_v2_speed_pilot_20261128/speed_validation.json](../3.Software/GravityCalibration/results/wrist_v2_speed_pilot_20261128/speed_validation.json)，其中 F1 平均速度与编码器位移除以 F4 经过时间所得速度的相对差为 0.25%–3.17%。

离线 65 姿态结果

| 项目 | 最大误差 | 验收阈值 |
| --- | ---: | ---: |
| HEAD 电流基线 | 0 A | < 1e-6 A |
| MJCF/C++ 腕力矩 65 姿态最大差 | 2.546e-7 N·m | < 1e-5 N·m |

可选独立校验脚本

```bash
python3 6.Tests/firmware/test_wrist_gravity.py
```

脚本使用当前 `scene.xml`、夹爪闭合值 `gripper_rad=0` 和固定随机种子生成 65 个姿态，与 F4 C++ 静态力矩逐项比较。缺少 MuJoCo 或 NumPy 时脚本以 SKIP 退出，不进入通用固件 run.sh 的强依赖。
