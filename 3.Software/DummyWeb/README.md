# DummyWeb · DummyRobot 本地控制台

基于本地 Python HTTP 桥接服务和 HTML/Three.js 页面，提供 DummyRobot 串口控制、关节/夹爪滑块、ASCII 指令窗口、D435 实时预览、关节状态遥测，以及 DummyMujoco URDF/MJCF 网格模型显示。Three.js 与 STLLoader 已放在 `static/vendor/`，页面运行不依赖 CDN。

## 启动

项目使用你已有的 `DummyRobot` Conda 环境。先确认环境里有 `pyserial`、`numpy`、`opencv-python` 和 `pyrealsense2`；若有缺失，只在该环境内安装：

```bash
conda activate DummyRobot
python -m pip install -r /home/xiaohai/workspace/DummyRobot/3.Software/DummyWeb/requirements.txt
```

启动本机服务：

```bash
cd /home/xiaohai/workspace/DummyRobot/3.Software/DummyWeb
./run.sh
```

浏览器打开 `http://127.0.0.1:8765`。服务默认只绑定本机回环地址，关闭终端或按 `Ctrl+C` 停止。

## 页面操作

1. 点端口旁的扫描图标，选择主控虚拟串口（例如 `/dev/ttyACM0`）。按主控固件配置选择波特率、数据位、校验位和停止位；当前参数默认 115200、8N1。USB CDC 不依赖波特率时，仍保留该选项用于串口驱动配置。
2. 点“连接机械臂”。必须先收到 `#GETSTATUS` 回包才报告连接成功；仅能打开 `/dev/ttyACM0` 不代表 F4 正常运行。连接后会轮询 `#GETSTATUS`、`#GETJPOS` 和 `#GETLPOS`，页面显示实际关节角和 TCP 姿态。
3. 点“使能”后可以拖动 J1–J6 滑块；拖动过程中按约 100 ms 节流持续发送目标关节角，松开时再兜底发送一次。使能和滑块控制会设置 `#CMDMODE 2`（INT）。所有关节目标命令统一使用 `>j1,j2,j3,j4,j5,j6,speed`，速度从 `config.json` 读取，默认 **30°/s**。
4. 夹爪可用滑块精调，也可以点“打开夹爪”或“关闭夹爪”；协议发送 `#GRIP angle`，范围默认 0–45°。现有固件没有夹爪角度回读接口，页面模型显示的是最后发出的夹爪目标角，不代表夹爪测得的实际位置。
5. “Homing”与“Resting”使用关节控制命令移动到配置文件中的姿态，不依赖固件增加新命令。默认姿态分别为 `[0, 0, 90, 0, 0, 0]` 和 `[0, -75, 180, 0, 0, 0]`。点击后会先弹出确认框；执行期间按钮显示 `Resetting…` / `Returning…`，到达目标或超时后恢复。
6. 点“连接相机”启动 D435 彩色/深度流，页面显示彩色预览；断开按钮停止相机流。
7. 页面中间自动加载 `dummy.xml`（MJCF）数字孪生，机器人实际关节反馈通过配置里的模型关节映射驱动 Three.js 模型。
8. 在“串口指令”面板输入一行 ASCII 数据，点击“发送”或按回车。面板原样发送并显示固件回包和错误；网页不判断指令是否受支持，也不校验速度、关节角或夹爪参数。常见运动、使能、夹爪和模式设置会要求二次确认；`!STOP` 可直接发送。

连接、使能和各轴故障状态从 F4 的 `#GETSTATUS` 读取。故障时页面显示轴号及原因，并锁定运动控件。排除原因、支撑好重力轴后点击“清除故障”（该操作会让驱动失能）；清除成功仍保持失能，需要重新使能、发送新目标。断开串口不会自动改变机械臂使能状态。需要同时更新 F4 和所有 F1；协议不匹配会阻止使能。

## 串口指令窗口与固件 ASCII 命令

页面指令窗口是单行 ASCII 透明发送终端：输入内容原样经 USB 虚拟串口发给固件，网页不限制指令类型、速度、关节角或夹爪参数，也不要求指令出现在下表中。固件负责解析、参数校验和安全判断；网页只拒绝空输入、换行和非 ASCII 字符，避免破坏串口帧。

下表是常用命令参考，不是白名单；新固件指令可以直接在窗口发送。

| 功能 | 命令格式 | 参数与行为 |
|---|---|---|
| 读取状态 | `#GETSTATUS` | 返回 `oks enabled mode fault_mask f1 f2 f3 f4 f5 f6`，各轴故障位见下文 |
| CAN 诊断 | `#GETCAN` | 返回收发、错误、中止计数及最近错误快照，详见文末诊断说明 |
| 控制耗时 | `#GETTIMING 1` 至 `#GETTIMING 6` | 返回 `okt 轴号 最近周期数 最大周期数 超预算次数`；需配套 F1/F4，72 MHz 时周期数除以 72 为微秒 |
| 驱动诊断 | `#GETDRV 1` 至 `#GETDRV 6` | 返回当前反馈年龄、驱动状态/故障、锁存故障、首次超时年龄和反馈累计数；不触发动作 |
| 清除故障 | `!CLEARFAULT` | 仅在 F4 停止/失能时允许；复位驱动故障及旧目标，确认六轴状态后返回 `Faults cleared ok`，不自动使能 |
| 读取关节角 | `#GETJPOS` | 返回 `okj J1 J2 J3 J4 J5 J6`，角度单位为度 |
| 读取末端位姿 | `#GETLPOS` | 返回 `okl X Y Z A B C`；XYZ 为毫米，ABC 为度 |
| 使能机械臂 | `!START` | 使能电机；页面会二次确认 |
| 失能机械臂 | `!DISABLE` | 失能电机 |
| 急停 | `!STOP` | 请求固件停止当前运动；页面可直接发送。急停后仍需检查实机状态 |
| 设置命令模式 | `#CMDMODE mode` | `1` 顺序目标点；`2` 可中断目标点（固件默认）；`3` 轨迹模式（仍按目标点处理，未实现完整轨迹跟踪）；`4` 电机调试；`5` 拖动示教。返回 `Set command mode to [n]` |
| 设置夹爪角 | `#GRIP angle` | 常用范围 `0` 到 `45` 度；页面会二次确认 |
| 设置夹爪电流上限 | `#GRIP_CURRENT current` | 常用归一化范围 `0` 到 `1`；页面会二次确认 |
| 关节目标（命令队列） | `>j1,j2,j3,j4,j5,j6,speed` | 模式 1 按顺序执行；模式 2 可中断当前目标。速度由输入决定，不替换为配置值 |
| 直线末端目标 | `@x,y,z,a,b,c,speed` | XYZ 为毫米，ABC 为度；速度由输入决定 |
| 重力前馈 | `#GRAVITY_FF_ON` / `#GRAVITY_FF_OFF` | 控制 F4 是否发送非零重力前馈；默认关闭 |
| 拖动增益 | `#DRAG_GAIN damping friction_alpha current_limit` | 设置拖动阻尼、摩擦补偿系数和关节电流上限 |
| 拖动参数查询 | `#GETDRAG` | 返回当前命令模式、使能状态和拖动增益 |

`>` 命令还支持夹爪扩展格式：`>j1,j2,j3,j4,j5,j6,speed,gripper_angle` 和九参数格式 `>j1,j2,j3,j4,j5,j6,speed,gripper_angle,gripper_current`。固件支持 6–9 参数的 `>` 和 6–7 参数的 `@`；有效入队回复为 `0–16`，`error ...` 为失败。网页不改写这些数值。

命令回包可能表示“已进入队列”或“命令已接收”，并不保证机械臂已经到位；请结合实时关节/TCP 遥测确认运动结果。`#CMDMODE 4` 是电机调试模式，普通 `>` / `@` 队列运动不适用于该模式。

Homing / Resting 不是 USB ASCII 命令，而是页面通过六关节目标实现的两个预设动作，也不是限位开关寻零。请先确认机械臂周围空间、关节限位、速度和目标姿态适合实机，再使能并运动。

## 故障信息

每个 `fN` 为按位组合：`1` 过载、`2` 堵转、`4` 编码器未校准、`8` CAN 反馈超过 250 ms、`16` F1 协议不兼容、`32` 运动等待超时（随目标时长调整，30 s–10 min）、`64` 驱动意外停止/重启、`128` F1 控制循环连续超预算。`fault_mask` 的 bit0–bit5 对应 J1–J6。F4/OLED 会锁存故障；反馈恢复不会自动恢复运动。更多调试步骤见 [驱动故障与恢复](../../5.Docs/驱动故障与恢复.md)。

OLED 旧格式 `FAULT J:25` 表示十六进制轴掩码 `0x25`（J1/J3/J6），`J:24` 表示 J3/J6；不是错误码 25/24。新版会轮换显示具体轴及原因，例如 `FAULT 0x24 J3:08` / `CAN TIMEOUT`。

如果收到 `assertion "Balloc succeeded" failed ... mprec.c`，说明 F4 的 newlib 浮点格式化分配失败，USB 任务可能已停在断言后的 `_exit()`，所以后续才表现为 Write timeout。本次 F4 已修复 `_sbrk` 错把 CCM 任务栈当作 SRAM 堆上限的问题，并加入分配锁和任务独立的 newlib 状态；需更新 F4 后重新上电，F1 无需为此修改。

若出现 `Write timeout`，且 OLED FPS 也停止变化，需要先修复/重启 F4；此次固件修复了 ASCII 入口栈帧超过 USB/UART 任务栈的问题。新版后端会报告失败的具体命令并关闭通信连接；不会自动重发运动，也不把关闭串口当作电机失能。点击“使能”会先查询 `#GETSTATUS`，该查询失败时并未发送 `!START`。更新后端后须重启服务；重新连接先验证遥测，再清错和使能。

## 可调参数

固定参数文件为 [`config.json`](config.json)，修改后重启服务生效：

- `server.host`、`server.port`：本地服务地址与端口；建议保持 `127.0.0.1`。
- `serial.*`：默认端口、115200 波特率、8 数据位、N 校验、1 停止位、读写超时、轮询频率。默认 100 ms（10 Hz），页面会限制并发状态请求，避免串口轮询堆积。
- `robot.joint_speed_deg_s`：关节滑块和 Homing/Resting 预设动作使用的速度；默认 30°/s。串口指令窗口中的速度由输入文本决定。
- `robot.joints[].min_deg/max_deg`：滑块和后端的关节范围，取自当前固件各电机角度限位。
- `robot.joints[].model_joint/model_sign/model_offset_deg`：实机轴到 URDF/MJCF 关节的映射、方向和零位偏置。当前 J3 映射偏置设为 -90°，按实际模型与实机关节方向核对后可调整。
- `robot.homing_pose_deg`、`robot.resting_pose_deg`：两个关节空间预设目标。
- `robot.gripper.*`：夹爪角范围、开/合角和模型手指关节映射。
- `camera.*`：彩色/深度分辨率、帧率和预览 JPEG 质量。
- `models.*`：DummyMujoco 中 URDF、MJCF 和 STL 网格目录。

页面里的波特率/帧格式是连接时选择的参数；滑块/预设动作速度和关节映射由此文件统一维护，串口指令窗口不套用这些限制。

### CAN 只读诊断

配套最新 F4 后，指令框支持 `#GETCAN`（总线收发、错误、中止计数及最近错误寄存器）和 `#GETDRV 1` 至 `#GETDRV 6`（每轴当前反馈年龄、F1 状态/故障、F4 锁存故障、首次超时年龄、反馈累计数）。这些查询在未使能或故障时也可使用，不会清错或运动。修改服务代码后重启 DummyWeb 才能在指令框使用新增命令。

`15ok` 是旧排查固件的入队回复与完成回复串行化错误；新版 F4 以整行互斥发送修复。网页继续要求独立的数字入队回复，不猜测拆分损坏的回包，也不自动重发运动。`FAULT 0x1F / 08` 表示 J1–J5 锁存过 CAN 超时；结合每轴反馈年龄/计数判断当前是否恢复，不能当作过载码。

控制周期修复版新增 `#GETTIMING 1..6`：计时覆盖正常控制和编码器采样，校准流程除外。F1 连续三次超过 45 us 计算预算时，本地请求保持并锁存 `128` 故障，迟到目标不能恢复运动；显式清错后仍需重新使能。累计超预算次数和历史最大耗时在清错后保留。此版需要更新全部 F1 和配套 F4，并重启后端加载新指令。
