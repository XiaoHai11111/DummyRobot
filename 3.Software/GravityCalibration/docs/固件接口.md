## 本次增加的 F4 接口

请求：

```text
#GETTELEM 2
```

成功响应（11 个以空格分隔的字段）：

```text
okm joint position_tick_ms velocity_tick_ms current_tick_ms q_deg dq_deg_s i_cmd_motor_a driver_state fault_flags status_supported
```

| 字段 | 含义 |
|---|---|
| `joint` | 1..6；不支持广播 |
| 三个 `*_tick_ms` | F4 `HAL_GetTick()` 的 CAN 接收时间，uint32 毫秒，约 49.7 天回绕 |
| `q_deg` | 与 `#GETJPOS` 一致的实际机械臂关节角；包含 `initPose` 偏置 |
| `dq_deg_s` | 已换算方向和减速比的关节速度 °/s；来自 F1 编码器速度估计 |
| `i_cmd_motor_a` | F1 输出电流指令，A，保留电机坐标符号，没有按减速比缩放 |
| `driver_state` | 最新位置反馈的 F1 状态，0 STOP、1 FINISH、2 RUNNING、3 OVERLOAD、4 STALL、5 NO_CALIB、6 CONTROL_OVERRUN |
| `fault_flags` | 本次读取的位置、电流、速度反馈故障位的并集；位定义沿用 `5.Docs/驱动故障与恢复.md` |
| `status_supported` | 位置反馈扩展状态是否有效；电流/速度帧自身必须为 v1 扩展状态才接受 |

行为：

1. 发 `0x21`、`0x22`、`0x23`，等到三个计数都出现新反馈；等待窗口最多 50 ms（CAN 发包等待和线程调度开销另计）。任何发送失败或反馈超时返回 `error ...`，不返回陈旧电流。
2. 电流/速度接收检查节点 1..6、标准数据帧、8 字节、`0xA1` 标志、有效状态、有限数值；电流范围 ±3.3 A。
3. 电流/速度反馈**不刷新位置通信看门狗**。采集不能掩盖位置反馈丢失。
4. 临界区只复制字段，不等待、不发包、不格式化。不会修改控制模式、目标、限流或 EEPROM。
5. 这三个值不是同一 F1 控制周期的原子快照；CAN 现有查询没有事务序号，正常的 `0x07` 回复也会更新位置。时间戳是接收时间而非测量时间。只适用于当前低速准静态实验，不能据此做高频惯量识别。

本次仅需更新 F4，前提是 F1 已运行仓库目前带 `0xA1` 状态的版本。老 F1 只有 5 字节反馈时会超时，需要先升级匹配版本。F1 程序区与编码器校准/配置区的保留方法沿用原有 README，不要全片擦除校准区。

## 坐标与单位

| 轴 | 减速比 N | 电机到关节符号 s | F4 `initPose` 默认值 ° | 软件限位 ° |
|---|---:|---:|---:|---|
| J1 | 50 | +1 | 0 | −170..170 |
| J2 | 30 | −1 | −75 | −75..90 |
| J3 | 30 | −1 | 180 | 35..180 |
| J4 | 30 | +1 | 0 | −180..180 |
| J5 | 30 | −1 | 0 | −120..120 |
| J6 | 50 | −1 | 0 | −720..720 |

```text
q_robot_deg = initPose_deg + s * 360 * position_motor_rev / N
dq_robot_deg_s = s * 360 * velocity_motor_rev_s / N
i_joint_equiv_A = s * i_cmd_motor_A
q_model_rad = radians(model_sign * q_robot_deg + model_offset_deg)
tau_robot = model_sign * tau_model
```

本次读取到的 `DummyWeb/config.json` 中模型符号都是 +1，J3 模型偏置 −90°，其余为 0。实际使用时读配置，不要再把 `initPose` 重复加到已经返回的 `q_deg` 上。电机符号与模型符号是两层映射，不要混用。模型 J6 范围与 F4 范围并不完全一致，离线预览会拒绝超出 MJCF 范围的输入。

## 后续 F1 前馈接口设计（尚未实现）

建议另分配未占用的 RAM 命令，例如 `0x0A SET_CURRENT_FF`；这是候选编号，正式实现前要再次检查全项目冲突。载荷可为 `float32 motor_current_ff_A + uint16 sequence + uint16 lease_ms`，启用开关另行约定。它**不能**复用 `0x03`，因为 `0x03` 会切换到纯电流模式；普通 F4 的 `0x07` 又会切回位置模式。

推荐实现位置：

1. CAN 回调仅验证/暂存数据，20 kHz 控制周期消费；禁 NaN/Inf、异常序号、超范围值。
2. F4 用全部实际关节角计算 `g(q)` 或经验电流模型，按 50–100 Hz 的起始设计频率发给各 F1；实测 CAN 负载和时间裕量后再提高。保留现有 200 Hz 位置目标更新。
3. F1 在 `CalcDceToOutput` 中将反馈输出和前馈相加，最终统一限幅；积分抗饱和必须感知**包含前馈的总输出**。现有 `IntegrateLimited<128>` 的非积分项和位移量要按定点单位改造，不能只在末尾加一行电流。DCE 最终右移 10 位，前馈进入该累加域时相应乘 1024，并检查整型范围。
4. 单独记录 `i_feedback`、`i_ff`、`i_total`、总限幅标志、前馈序号和剩余租约。位置 PID/DCE 积分原本可能已承担重力；渐增前馈并处理积分状态，避免瞬间双倍补偿。
5. 普通前馈更新用变化率限制；超时撤去前馈并保持位置闭环。STOP/故障/禁用/清错/重启/模式切换必须清掉前馈状态，禁止旧包恢复后自动重放。现有故障保持逻辑继续优先执行。
6. 时间预算保持 F1 当前 20 kHz / 50 µs；已有 45 µs 连续超预算检测和 `#GETTIMING`，上线前测最后值、最大值、超预算计数及总线错误。

`calibration.py:limited_feedforward` 是离线限幅/限速参考，不是已部署的 F1 控制器。

## 后续同步采样设计（动态识别前完成）

增加版本化能力查询，并在 F1 控制周期锁存 `q,v,i_cmd`、可用的实测电流、目标值、模式、限流状态、控制周期计数和故障位。经典 CAN 一帧只有 8 字节，需要拆成多帧，每帧带同一序号，F4 完整组包或整组丢弃。避免只在接收函数里连续调用三个 getter 就称为同步；20 kHz 中断仍可能夹在其中。

六块 F1 时钟互不相同；多轴动态识别还要广播触发/时钟映射或其他同步机制。由完整快照周期号换算时间，检查重复、丢包、乱序，不能只给 PC 串口到达时刻。

## 后续拖动模式设计（尚未实现）

F4 必须有独立模式停止周期发送位置 `0x07`，并让 F1 明确支持重力电流、阻尼与期限约束。当前单次 `set_current()` 加 `#CMDMODE 4` 不等价于拖动模式：该模式是已有调参功能，未建立六轴重力和通信中断保护。

拖动模式下增加本地关节软限位、速度限制、失联保持、低阻尼稳定性检查和模式切换握手；纯电流模式时只有 F4 的 MoveJ 目标限位是不够的。必须先通过完整方案的力矩映射和多姿态验证。
