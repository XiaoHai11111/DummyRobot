# 固件接口与后续实现

## 已核实的现有链路

以下路径相对于仓库根目录：

| 路径/函数 | 事实及意义 |
|---|---|
| `2.Firmware/Ctrl-Step-Driver-STM32F1-fw/Ctrl/Motor/motor.cpp` / `GetFocCurrent` | 返回 `focCurrent/1000`，单位 A |
| 同文件 `CalcCurrentToOutput` | `focCurrent=current`；按正负方向选择编码器位置 ±90° 电角度，输出电流矢量 |
| 同文件 `CalcDceToOutput` | 位置/速度误差经 DCE 和积分得到电流，随后按 `ratedCurrent` 限制 |
| `.../Ctrl/Driver/tb67h450_base.cpp` | 电流指令转为双相 VREF，未读取真实相电流 |
| `.../Core/Src/adc.c` | PA0/PA1 两通道 ADC DMA 已初始化，但未找到将采样转换为真实相电流并上报的路径 |
| `.../UserApp/protocols/interface_can.cpp` | `0x21` 电流指令 A；`0x22` 编码器估计的电机转速 rev/s；`0x23` 电机位置 rev |
| `2.Firmware/Core-STM32F4-fw/UserApp/main.cpp` | `Timer(...,200)` 驱动控制任务；普通位置模式周期发送位置指令 |
| `.../Robot/instances/dummy_robot.cpp` | 关节方向、减速比、软件限位以及实际角度偏置 |

因此第一步应是**补齐 F4→USB 采集链路并注明电流来源**。如果一定要读取实测电流，必须另做硬件信号核对、采样同步、零偏/增益标定和电角度变换。现有两个 ADC 通道的存在不能证明它们接在电流采样点上。

## 本次增加的 F4 接口

请求：

```text
#GETTELEM 2
```

成功响应（11 个以空格分隔的字段）：

```text
okm joint position_tick_ms velocity_tick_ms current_tick_ms q_deg dq_deg_s i_cmd_motor_a driver_state fault_flags status_supported
```

| 字段 | 含义 |
|---|---|
| `joint` | 1..6；不支持广播 |
| 三个 `*_tick_ms` | F4 `HAL_GetTick()` 的 CAN 接收时间，uint32 毫秒，约 49.7 天回绕 |
| `q_deg` | 与 `#GETJPOS` 一致的实际机械臂关节角；包含 `initPose` 偏置 |
| `dq_deg_s` | 已换算方向和减速比的关节速度 °/s；来自 F1 编码器速度估计 |
| `i_cmd_motor_a` | F1 输出电流指令，A，保留电机坐标符号，没有按减速比缩放 |
| `driver_state` | 最新位置反馈的 F1 状态，0 STOP、1 FINISH、2 RUNNING、3 OVERLOAD、4 STALL、5 NO_CALIB、6 CONTROL_OVERRUN |
| `fault_flags` | 本次读取的位置、电流、速度反馈故障位的并集；位定义沿用 `5.Docs/驱动故障与恢复.md` |
| `status_supported` | 位置反馈扩展状态是否有效；电流/速度帧自身必须为 v1 扩展状态才接受 |

行为：

1. 发 `0x21`、`0x22`、`0x23`，等到三个计数都出现新反馈；等待窗口最多 50 ms（CAN 发包等待和线程调度开销另计）。任何发送失败或反馈超时返回 `error ...`，不返回陈旧电流。
2. 电流/速度接收检查节点 1..6、标准数据帧、8 字节、`0xA1` 标志、有效状态、有限数值；电流范围 ±3.3 A。
3. 电流/速度反馈**不刷新位置通信看门狗**。采集不能掩盖位置反馈丢失。
4. 临界区只复制字段，不等待、不发包、不格式化。不会修改控制模式、目标、限流或 EEPROM。
5. 这三个值不是同一 F1 控制周期的原子快照；CAN 现有查询没有事务序号，正常的 `0x07` 回复也会更新位置。时间戳是接收时间而非测量时间。只适用于当前低速准静态实验，不能据此做高频惯量识别。

本次仅需更新 F4，前提是 F1 已运行仓库目前带 `0xA1` 状态的版本。老 F1 只有 5 字节反馈时会超时，需要先升级匹配版本。F1 程序区与编码器校准/配置区的保留方法沿用原有 README，不要全片擦除校准区。

## 坐标与单位

| 轴 | 减速比 N | 电机到关节符号 s | F4 `initPose` 默认值 ° | 软件限位 ° |
|---|---:|---:|---:|---|
| J1 | 50 | +1 | 0 | −170..170 |
| J2 | 30 | −1 | −75 | −75..90 |
| J3 | 30 | −1 | 180 | 35..180 |
| J4 | 30 | +1 | 0 | −180..180 |
| J5 | 30 | −1 | 0 | −120..120 |
| J6 | 50 | −1 | 0 | −720..720 |

```text
q_robot_deg = initPose_deg + s * 360 * position_motor_rev / N
dq_robot_deg_s = s * 360 * velocity_motor_rev_s / N
i_joint_equiv_A = s * i_cmd_motor_A
q_model_rad = radians(model_sign * q_robot_deg + model_offset_deg)
tau_robot = model_sign * tau_model
```

本次读取到的 `DummyWeb/config.json` 中模型符号都是 +1，J3 模型偏置 −90°，其余为 0。实际使用时读配置，不要再把 `initPose` 重复加到已经返回的 `q_deg` 上。电机符号与模型符号是两层映射，不要混用。模型 J6 范围与 F4 范围并不完全一致，离线预览会拒绝超出 MJCF 范围的输入。

## F1 前馈接口（已实现离线模型版本，需上机验证）

已使用未占用的 RAM 命令 `0x0A SET_CURRENT_FF`，载荷为 `float32 motor_current_ff_A + uint16 sequence + uint16 lease_ms`；它不切换控制模式。`0x0B SET_DRAG_CURRENT` 使用相同载荷，进入有租约的电流模式。`0x26 GET_FF` 返回 `int16 i_feedback_mA`、`int16 i_ff_mA`、`int16 i_total_mA`、状态位和 `0xA2` 标记。

F1 配置默认值在 `Motor()` 构造函数的 `config.ctrlParams.feedForward` 中，`maxCurrent` 与 `dragCurrentAcc` 在 `main.cpp` 中显式配置。租约由 `MotionPlanner::CONTROL_TICKS_PER_MS` 换算，该值由现有 `CONTROL_FREQUENCY` 派生，不是独立定时器参数。序号比较是 `Controller` 的私有静态函数。

F4 在位置模式下以 50 Hz 发送前馈；`0x0A` 的反馈输出、前馈和总输出共享限幅，`IntegrateLimited` 的 anti-windup 输入包含前馈。超时、STOP、故障、禁用、清错、重启和切换出位置模式都会撤去前馈。`#GRAVITY_FF_ON` / `#GRAVITY_FF_OFF` 控制是否发送非零前馈，默认关闭。

当前重力模型使用 URDF 的关节链、质量与质心计算 J2/J3 广义重力力矩，并用 P0/P1/P2/P3 的实测曲线标定安培/牛顿米比例和偏置。它覆盖到的关节范围由 F4 软件限位约束，不再要求其他五轴停留在某个标定姿态；J1/J4/J5/J6 的重力前馈仍为零。该模型依赖当前末端负载，换负载后需重新标定比例；闭环前仍需实机验证。

`calibration.py:limited_feedforward` 是离线限幅/限速参考，不是已部署的 F1 控制器。

## 同步采样设计（动态识别前完成）

增加版本化能力查询，并在 F1 控制周期锁存 `q,v,i_cmd`、可用的实测电流、目标值、模式、限流状态、控制周期计数和故障位。经典 CAN 一帧只有 8 字节，需要拆成多帧，每帧带同一序号，F4 完整组包或整组丢弃。避免只在接收函数里连续调用三个 getter 就称为同步；20 kHz 中断仍可能夹在其中。

六块 F1 时钟互不相同；多轴动态识别还要广播触发/时钟映射或其他同步机制。由完整快照周期号换算时间，检查重复、丢包、乱序，不能只给 PC 串口到达时刻。

## 拖动模式（已实现受限版本，需上机验证）

`#CMDMODE 5` 进入 DRAG。该模式停止 200 Hz 位置目标，改以 200 Hz 发送 `0x0B`、200 ms 租约的电流命令，并周期性查询位置/速度。租约超时由 F1 本地转位置保持，但不闭锁新的有效拖动命令；退出 DRAG 时 F4 广播 Hold 并恢复位置闭环。

控制量为 J2/J3 全姿态重力估计，并可叠加阻尼和摩擦补偿。实机对照显示，速度反馈经 CAN 往返后再做阻尼会因延迟和速度量化产生震颤：默认阻尼 `0`，默认摩擦补偿系数 `0`，关节电流上限 `1.0 A`。保留 `#DRAG_GAIN <damping> <frictionAlpha> <currentLimit>` 作为调参接口，但只有在 F1 本地低延迟速度环实现后才建议启用非零阻尼；`#GETDRAG` 查询。F1 拖动电流爬升默认 `20 A/s`，避免重力补偿尚未建立时先下坠。J1/J4/J5/J6 当前没有重力补偿。

F4 侧保留软件限位附近抑制外推电流、速度超过 30 °/s 时抑制同向助力、速度反馈低通滤波、禁用/故障自动 Hold。位置环和调参模式 4 与拖动模式完全分离；`0x0B` 租约到期或 CAN 中断会消除持续输出，但完整的硬件急停、机械限位和失联保持仍需实机验收。

DummyWeb 的 `#GETSTATUS` 解析已接受模式 5，拖动模式下可以正常连接和轮询状态。
